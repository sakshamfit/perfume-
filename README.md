# VELORA Paris — scroll-directed fragrance editorial

A single-page fragrance launch site: ivory curtain intro, full-bleed product hero, per-word scroll-scrubbed manifesto, asymmetrically staggered note cards, a pinned bottle stage, interactive composition tabs, journal/news cards, and a closing campaign — all driven by one scroll playhead.

No templates, no animation library presets: every motion on the page is a hand-authored GSAP timeline, and the styling is a bespoke CSS system rather than utility soup.

> **Provenance.** This repository is an adaptation of the open-source [`gireeshkumarreddy/velora`](https://github.com/gireeshkumarreddy/velora) site — the page design and its component code come from there, credited in the footer. What is built *here* is the tooling layer around it: the data extraction pipeline, the readiness scorer, the generated component catalogue, the design/skill documentation, the reuse recipes, and the footer/attribution work. I keep the origin explicit because pretending a fork started from an empty directory is a claim that falls over the moment anyone reads `git log`. Everything below documents the whole system as it now stands.

## What's interesting about the build

**One clock for all motion.** Lenis does not run its own rAF loop; it rides GSAP's ticker (`gsap.ticker.add(tick)`) and pushes its scroll events into `ScrollTrigger.update`. That single decision is what removes the micro-jitter every "smooth scroll + scrub" site has.

**Scrubbed, not animated.** Nothing on the page plays on entry. Every continuous effect is bound to scroll position with `ease: "none"` (`scrub: 0.6` for copy, `0.8` for cards, `1.2` for photography) so the wheel *is* the playhead. Only the one-shot line reveals get a named ease.

**Pinning that survives the real world.** The pinned product stage is registered inside `gsap.matchMedia().add("(min-width: 800px)")`, and `ScrollTrigger.refresh()` is called on `document.fonts.ready`, on `load`, and on a 2.5 s timer — because pins mis-measure until webfonts and lazy images settle. The same effect is re-registered on locale change, since French copy is longer than English and every start/end position was measured in English.

**Accessibility as an implementation detail, not a checklist item.** Native `<dialog>` + `showModal()` for all six overlays (focus trap, `Esc`, backdrop hit-test dismissal); a skip link; `role="tablist"` on the note tabs; `role="status"` toast; `aria-hidden` on the three decorative ghost wordmarks; `:focus-visible` ring; `scroll-padding-top` so anchors don't land under a fixed header; intrinsic `width`/`height` on every image so scrubbed parallax can't reflow anything; and a single `prefers-reduced-motion` gate that skips the entire motion effect *and* releases the intro curtain instantly.

**Overlay system with no dependency.** One `<dialog>`, one `panel` union type (`search | bag | product | menu | journal | care | null`), content switched by state, Lenis paused while open, `data-lenis-prevent` on the scroll body. Roughly 40 lines that would otherwise be three libraries.

**Honest pre-launch commerce.** Add/remove/quantity clamped to `0..20`, mirrored to `localStorage` with validated reads, plus "save my selection" which serialises to a Blob and downloads a text file. No backend, no fake confirmation.

**The mark is an SVG colour matrix.** A `feColorMatrix` turns luminance into alpha, so the logo is derived from the supplied photograph with no redrawing and no distortion — one asset, light and dark treatments.

**Content is data, extractable and scoreable.** All copy lives in a keyed dictionary that a script reflects into JSON; another script scores the *data* (i18n parity, entity completeness, media readiness, a11y, perf hygiene, maintainability) and writes `docs/DATA-SCORE.md`. The report is measured from files, so it moves when the project moves.

## Getting started

Requires Node `>=22.13.0` and pnpm (`packageManager: pnpm@11.25.0` — use corepack).

```bash
corepack enable
pnpm install            # or: pnpm run install:ci
pnpm dev                # vinext dev server on :5173
DEV_ALLOW_ALL_HOSTS=1 pnpm dev   # also bind 0.0.0.0 and skip the Host allow-list
                                  # (for tunnel/preview access; off by default)

pnpm lint               # eslint 9, next core-web-vitals + typescript
npx tsc --noEmit        # strict type-check
pnpm build              # production build (Cloudflare Worker target)
```

Data + docs pipeline (plain Node — runs with zero installs):

```bash
pnpm data:extract   # app/page.tsx   -> data/site-content.json
pnpm data:check     # CI guard: fails when the JSON is stale
pnpm data:score     # data/*.json + public/assets -> docs/DATA-SCORE.md
pnpm docs:components# components/** -> docs/COMPONENT-CATALOG.md
pnpm docs:build     # all three, in order
```

## Architecture

```
app/
  layout.tsx        # metadata, fonts loaded via CSS (self-hosted OTF)
  page.tsx          # everything renderable: copy dictionary, sections, motion, overlays
  globals.css       # 2 247 lines: tokens, sections, modals, 6 breakpoints, reduced motion
  chatgpt-auth.ts   # dormant auth helper for the hosting platform
components/
  ui/*.tsx          # 61 shadcn-style primitives (installed, not imported by the page)
  connector-error.tsx
data/
  site-content.json # GENERATED: full EN/FR dictionary, assets map, section anchors
  site-model.json   # curated: product, notes, 8 sections w/ animation specs,
                    # news/journal, policies, search index, media ledger, state, gaps
docs/
  DATA-SCORE.md         # GENERATED: readiness score + rubric + priority fixes
  COMPONENT-CATALOG.md  # GENERATED: every component, its deps, and reuse recipes
  STACK-SKILLS.md       # every technique in the build + how to reproduce it
  DESIGN-TOKENS.md      # colours, type scale, spacing, motion tokens, breakpoints
  REUSE-GUIDE.md        # copy-paste recipes for lifting these patterns elsewhere
hooks/use-mobile.ts     # matchMedia hook (starter, unused here)
lib/utils.ts            # cn()
db/ + drizzle/          # intentionally empty; opt-in D1 example in examples/d1/
scripts/                # data extraction, scoring, catalogue generation, install/build infra
public/assets           # hero / bottle / notes (WebP) + brand reference + 3 self-hosted fonts
```

**Data flow today:** `app/page.tsx` is the source of truth → `extract-site-data.mjs` reflects it into JSON → `score-data.mjs` audits that JSON against the files on disk. Flipping the arrow (JSON in, page renders from it) is the first refactor; `docs/REUSE-GUIDE.md` §11 has the plan.

**Deploy model:** `vite.config.ts` + `@cloudflare/vite-plugin` build a Worker (`build/sites-worker.ts`), with local D1/R2 bindings read from `.openai/hosting.json`. `db/schema.ts` is deliberately empty, so nothing in the page depends on a database.

## Scoring

`docs/DATA-SCORE.md` is generated, not typed. Current dimensions and weights:

| Dimension | Weight | What 100 means |
| --- | --- | --- |
| i18n parity | 12% | every key present, non-empty, genuinely localised |
| Entity completeness | 18% | product/notes/media all carry real values |
| News reusability | 14% | each article has a bilingual body *and* slug, author, date, unique cover |
| Media readiness | 18% | inside a 1.5 MB imagery budget, alt text, intrinsic sizes, best format wired |
| Structure & spec | 12% | every section mapped to components + copy keys + motion specs |
| Accessibility | 10% | 10-check pass list |
| Performance hygiene | 8% | 9-check pass list |
| Maintainability | 8% | small components, split styles, motion not bound to class strings, tests, licence |

Run it after any content or asset change; the priority-fix list is derived from the same measurements.

## Known gaps (measured, not vibes)

- Lossless WebP in the render path: ~6.9 MB of imagery where 3.1 MB of lossy twins already sit unreferenced.
- `brand-reference.png` is a 2.2 MB source loaded to be CSS-cropped into a wordmark.
- `components/ui/*` is a dormant library: `app/globals.css` defines none of the tokens those files need (`bg-background`, `text-muted-foreground`, …), so importing one today renders unstyled.
- Journal/news entries have no `slug`/`author`/`publishedAt`, so they can't be linked or paginated.
- No price, SKU, inventory or INCI data, so checkout work can't start.
- 1 388-line component, 2 247-line stylesheet, six tweens keyed to global class names, zero tests.
- `pnpm lint` fails with 2 inherited `react-hooks/set-state-in-effect` errors and 15
  `no-img-element` warnings (`tsc --noEmit` is clean) — triage documented in
  `docs/STACK-SKILLS.md` §9.
- **No licence file upstream** — see below.

## Notes for the next developer

- `pnpm-workspace.yaml` here is not a monorepo; it is a supply-chain policy file (`minimumReleaseAge: 10080`, `strictDepBuilds`, explicit `allowBuilds`). Copy it into your next project — it's the cheapest protection available.
- `eslint.config.mjs` disables three rules for `components/ui/**` because those files are vendored verbatim from the registry. Same trick works for any `vendor/` directory.
- Images are versioned by filename (`-clear`) rather than query strings, so a soft cached asset can never be reused.
- `799px` (CSS) and `800px` (GSAP `matchMedia`) are the same boundary expressed twice. Move one, move both.
- **`build/` is source, not output.** Five files (`sites-vite-plugin.ts`, `sites-worker.ts`,
  `connector-preview-*`) that `vite.config.ts` imports, despite the name. It is not in
  `.gitignore` and must not be deleted or regenerated; tooling that prunes directories
  called `build`/`dist` will break the dev server. The one true artifact is `dist/`.
