## Priority fixes

### Swap the lossless WebP render path for the lossy twins  
_high impact · app/page.tsx_

hero/notes/bottle are delivered as lossless WebP (6915 KB total). The lossy versions already in `public/assets` are 3118 KB — roughly 2.2x smaller — and are currently unreferenced. Re-point `assets` in `app/page.tsx` (or emit `.webp` + `.avif` and let `<picture>` negotiate).

### Stop loading the full brand photo to render a wordmark  
_high impact · app/page.tsx#Brand_

`Brand` renders a 2256 KB PNG and clips it, purely to reproduce the mark. Bake the cropped mark to SVG once; the payload drops by ~2 orders of magnitude and the SVG luminance filter (`#velora-mark-light` / `#velora-mark-dark`) is no longer needed for transparency.

### Give the journal entries real fields  
_medium impact · data/site-model.json#news_

News/journal items carry body copy but no slug, author or date, so they cannot be linked, listed or paginated. The shapes are already reserved in `data/site-model.json` — add values (only real ones) and the JSON becomes the payload for a `/journal/[slug]` route or a CMS import.

### Decouple animation wiring from CSS class names  
_medium impact · app/page.tsx#useEffect_

6 tweens target global selectors (`.hero-photo`, `.scent-card`, ...). Refactoring markup silently breaks them. Return refs from a `useScrollScene` hook or use `data-animate="hero-photo"` attributes so markup and motion can change independently.

### Fill the commerce gaps before wiring a checkout  
_medium impact · data/site-model.json#product_

The product record has no price, SKU, inventory or INCI list (see `product.missing`). Any cart work needs those first — inventing them for a demo is how a launch gets pulled.

### Split the 1365-line page component  
_low impact · app/page.tsx_

Copy dictionary, section markup and scroll effects all live in one file. Extract `content` into `data/site-content.json` (done — read it in), then one component per section. Each section becomes reusable in the next landing page.
